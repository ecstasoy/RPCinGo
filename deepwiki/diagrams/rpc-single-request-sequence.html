RPCinGo Request Flow

Single Request Sequence

一次 RPC 从应用层发起，到客户端拦截器、服务发现/连接池、TCP 协议编解码、服务端拦截器、业务方法执行，再到响应按 RequestID 回到原调用方的完整链路。

关键配对点

  • Request 创建时生成唯一 ID。
  • 客户端把等待者挂到 `pending[req.ID]`。
  • 响应回来后靠 `RequestID` 找回原调用方，不靠返回顺序。

并发模型

  • 客户端用 `writeMu` 串行写 socket，避免请求帧交错。
  • 服务端每个请求独立 goroutine 执行 handler。
  • 服务端写回统一走 writer goroutine，避免响应帧交错。

拦截器位置

  • 客户端拦截器包住整个出站调用。
  • 服务端拦截器包住整个入站处理。
  • 所以调用形态接近 `client -> tcp -> server -> handler -> tcp -> client`。
