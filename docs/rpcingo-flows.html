RPCinGo · 链路可视化预览

自研 Go RPC 框架 — 模块分层 · 端到端调用链 · 拦截器洋葱 · 线协议帧 · 熔断 FSM

1

模块分层依赖图

自底向上 7 层：线协议 → 连接池 → 客户端/服务端 → 拦截器 → 注册中心/负载均衡 → 韧性 → 可观测性（横切）

2

端到端 RPC 调用链路（9 阶段）

Discovery 模式 + 追踪 + 重试 + 熔断的一次 typed call —— 蛇形：客户端出站 → TCP → 服务端 → 响应回程

3

拦截器洋葱链（客户端 · 服务端）

同一 Interceptor 类型 + Chain() —— 先注册 = 最外层；服务端每次请求重建 NewChain；熔断在 invoker 内部、被 Retry 包裹

4

线协议帧布局（20 字节定长头 + 变长 body）

大端序自描述帧 —— Codec / Compress 写在头里，接收方无需协商即可解码解压

5

熔断器三态机 + 限流器

10 桶滑动时间窗统计 · 位于 invoker 内部（非拦截器）· 仅 Discovery 模式、per-service

调用链 9 阶段（A→I）

  • • A 客户端准备：ctx 超时 + NewRequest
  • • B 客户端拦截器（外→内）
  • • C invoker：发现 + LB + 连接池
  • • D 线协议出站：编码/压缩/分帧
  • • E 服务端入站：读帧 + 信号量限流
  • • F 服务端拦截器 + 反射派发
  • • G 构造响应 / mapError
  • • H 客户端 readLoop 按 RequestID 路由
  • • I 回溯拦截器 + CallTyped 解码

关键不变量

  • • RequestID 由传输层独占（per-conn 计数器）
  • • 编码侧静态、解码侧按帧头动态
  • • writer 关闭序：handlersWg → close(writeCh) → writerWg
  • • 拦截器链每次请求重建（NewChain）
  • • 熔断在 invoker 内部，被 Retry 包裹
  • • 追踪上下文藏在 req.Metadata

易踩的坑

  • • 线上无 cancel 帧：HandlerTimeout 是服务端唯一预算
  • • NewClient(fixed) 忽略 Discovery/LB/熔断选项
  • • etcd watcher 每个 WatchResponse 只取首个事件
  • • etcd lease 掉线后不重建（沉默死亡）
  • • Metrics 标签无界基数（service/method 取自请求）
  • • HandleRequest 永返 (*Resp, nil)
