RPCinGo — System Architecture

Client flows top-to-bottom through Call → Interceptors → Pool → TCP. Server flows bottom-to-top. They meet at the 20-byte binary protocol on the wire.

Wire Protocol

  • Magic bytes 0xCAFE identify RPCinGo frames
  • 20-byte fixed header, always read first
  • JSON or Protobuf body encoding
  • Optional Gzip / Snappy compression
  • TCP multiplexing via 8-byte RequestID

Interceptor Chain

  • Client: Retry → RateLimit → CircuitBreaker → Tracing
  • Server: Recovery → Logging → Metrics → Tracing
  • Onion-model middleware composition
  • Full context propagation across chain

Infrastructure

  • etcd service registry with watch streams
  • Prometheus metrics export via interceptor
  • Jaeger / OTEL distributed tracing
  • In-memory registry for unit testing
